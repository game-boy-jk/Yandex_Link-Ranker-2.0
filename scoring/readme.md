# Link Ranker

Проект ищет товарные ссылки через Yandex Search API и выбирает до 3 самых
подходящих результатов под закупочный запрос.

Скрипт смотрит на `title`, `url`, `passages`, числа, размеры, модельные коды и
товарные признаки. На выходе остаются ссылки, которые больше похожи на реальные
карточки товара, а не на инструкции, обзоры или мусор из выдачи.

## Быстрый запуск

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

Создать `.env` в корне проекта:

```text
YANDEX_API_KEY=ваш_api_ключ
YANDEX_FOLDER_ID=ваш_folder_id
```

Одиночный поиск:

```powershell
python main.py "Гайка шестигранная нормальная оцинкованная ГОСТ 4032-2014"
```

Если ничего подходящего нет, скрипт так и напишет:

```text
Ничего не нашлось
```

## Web-интерфейс

Запуск:

```powershell
python -m webapp.server
```

Открыть:

```text
http://127.0.0.1:8000
```

Через страницу можно загрузить CSV/XLSX, следить за прогрессом, отменить
обработку, скачать результат и сделать одиночный поиск. История и временные
файлы лежат в `web_data`.

## CSV и XLSX

Файл может быть простым списком в один столбец или таблицей с заголовками.
Колонки ищутся по обычным названиям: `query`, `запрос`, `наименование`,
`название`, `товар`, `name`, `product`.

Примеры:

```powershell
python main.py --file ".\queries.csv"
python main.py --file ".\список запросов.xlsx" --column "Наименование"
python main.py --file ".\queries.csv" --output-dir ".\ready" --workers 3
```

Результат сохраняется в CSV. Для каждой строки будет статус: `found`,
`not_found` или `error`. Если один запрос сломался, весь файл не падает.

## Docker

Если хочется запускать web-интерфейс в контейнере:

```powershell
docker compose up --build
```

Контейнер берёт ключи из `.env`. Папки `web_data` и `results` проброшены наружу,
поэтому история и готовые файлы остаются на компьютере.

## macOS

Есть простой скрипт:

```bash
chmod +x run_mac.sh
./run_mac.sh "Гайка шестигранная нормальная оцинкованная ГОСТ 4032-2014"
```

Он создаст `.venv`, поставит зависимости и запустит `main.py`.

## Диагностика

Если нужно посмотреть, что Яндекс вернул до нашего скоринга:

```powershell
python main.py --passages "гайка М16 ГОСТ 4032"
```

Это больше команда для проверки и настройки. Обычному пользователю она обычно
не нужна.

## Что учитывает скоринг

Основные вещи:

- похожесть текста через RapidFuzz;
- совпадение слов, чисел и размеров;
- `passages`, если Яндекс их вернул;
- модельные коды и точные идентификаторы;
- товарные признаки и `offers`;
- штрафы за неподходящие страницы;
- фильтр плохих доменов.

Сначала ранкер берёт ссылки с высоким скорингом. Если хороших результатов меньше трёх,
он может добрать ссылки из более слабых кандидатов. Такие ссылки всё равно сортируются ниже и получают штрафы в диагностической причине,
но помогают не схлопывать выдачу до одного результата,
когда Яндекс вернул мало точных совпадений.


## Ограничения

Инструмент зависит от того, что есть в индексе Яндекса. Если нужного товара нет в открытой выдаче, скрипт не сможет его найти.
Проект помогает быстро отсеять мусор и получить первые релевантные ссылки, но финальное решение всё равно остаётся за человеком.
Но ответ может быть неточным, так как сам Яндекс иногда выдаёт не то что мы хотим по смыслу. Да, да вот так вот.
И чем меньше слов в запросе и грамотнее составлен, тем точнее и лучше будет вывод.
